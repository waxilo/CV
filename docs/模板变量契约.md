# 模板变量契约 v1

> 模板作者参考手册。定义「用户填写的简历 JSON」如何转换为模板可用的变量。
>
> 配套文档：[模板引擎 v2 设计方案](./模板引擎-v2-设计方案.md)
>
> `contextVersion: 1`

---

## 0. 契约的意义

用户填写的所有信息存在**一份 JSON** 里（`resume.data`，类型 `IResumeData`）。模板不直接消费这份原始 JSON，而是消费 `buildRenderContext()` 产出的**渲染视图模型**。

原因：原始 JSON 里 `sections` 是数组、每类条目字段名各异、日期是裸字符串。若直接暴露，每个模板作者都要重写一遍索引、字段分支和日期格式化逻辑。

```
resume.data (IResumeData)  ──buildRenderContext()──▶  ctx (IRenderContext)  ──▶  模板
   用户的数据                     归一化 + 派生字段              稳定契约
```

**兼容承诺**：往契约里新增字段不升 `contextVersion`；重命名或删除字段才升版本，届时旧模板按其声明的 `meta.contextVersion` 走降级适配。

## 1. 顶层变量

| 变量 | 类型 | 说明 |
| --- | --- | --- |
| `basics` | object | 基本信息，见 §2 |
| `sections` | array | **已排序、已过滤隐藏项**的模块列表，见 §3 |
| `s` | object | 按 `type` 索引的模块，如 `s.experience`，见 §3.1 |
| `vars` | object | 模板变量的实际取值，见 §6 |
| `page` | object | 页面尺寸与页边距，见 §7 |
| `meta` | object | `templateId` / `generatedAt` |
| `helpers` | object | 辅助函数，见 §5（HTML 引擎里作为过滤器使用） |
| `contextVersion` | number | 固定 `1` |

两种引擎的取值写法（Vue 引擎当前尚未启用，写法先记录在此）：

| | HTML 引擎 | Vue 引擎（未启用） |
| --- | --- | --- |
| 插值 | `{{basics.name}}` | `{{ basics.name }}` |
| 循环 | `{{#each sections}}...{{/each}}` | `v-for="sec in sections"` |
| 条件 | `{{#if basics.email}}...{{/if}}` | `v-if="basics.email"` |
| 富文本 | `{{& item.descriptionSafe}}` | `v-html="item.descriptionSafe"` |

### 1.1 真值判定

`{{#if}}` / `{{#unless}}` 的判定规则与 JavaScript 有两处刻意的差别：

| 值 | 判定 | 说明 |
| --- | --- | --- |
| `null` / `undefined` / `false` | 假 | |
| `''` 空字符串 | 假 | |
| `[]` 空数组 | **假** | JS 里空数组是真值。模板里 `{{#if items}}` 想表达的是「有内容」 |
| `0` | **真** | JS 里 0 是假值。`level: 0` 是有效取值，不该被当成缺失 |
| 其他 | 真 | |

### 1.2 循环内的特殊变量

只在 `{{#each}}`（以及 Mustache 形式的 `{{#key}}` 数组迭代）内部可用：

| 变量 | 说明 |
| --- | --- |
| `this` | 当前条目本身，字段可写 `{{this.title}}` 或省略前缀写 `{{title}}` |
| `@index` | 序号，从 0 开始 |
| `@number` | 序号，从 1 开始 |
| `@first` / `@last` | 是否首项 / 末项 |
| `@length` | 当前迭代的总条数 |

裸字段名（`{{title}}`）的查找顺序是：当前条目 → 外层条目 → 顶层上下文。所以在循环里也能直接取到 `{{vars.primaryColor}}` 这类全局变量。

## 2. `basics`

来源：`resume.data.basics`（`IResumeBasics`）。

| 字段 | 类型 | 来源 | 说明 |
| --- | --- | --- | --- |
| `name` | string | `basics.name` | 姓名，可能为空 |
| `headline` | string | `basics.headline` | 求职方向 / 一句话介绍 |
| `email` | string | `basics.email` | |
| `phone` | string | `basics.phone` | |
| `location` | string | `basics.location` | |
| `url` | string | `basics.url` | 个人主页 |
| `avatarUrl` | string | `basics.avatarUrl` | 派生：非法协议会被置空；Vue 引擎在 `allowRemoteImages=false` 时会先转为 `data:` URL |
| `initial` | string | 派生 | `name` 首字，头像占位用；`name` 为空时为 `?` |
| `contacts` | array | 派生 | **已过滤空值**的联系方式列表 |

`contacts[]` 条目：

| 字段 | 说明 |
| --- | --- |
| `key` | `email` / `phone` / `location` / `url` |
| `label` | 中文标签：`邮箱` / `电话` / `所在地` / `主页` |
| `value` | 显示文本 |
| `href` | 可点击链接：`mailto:` / `tel:` / `''`（location 无链接）/ 原 url |

用 `contacts` 而不是逐个判空，是为了避免模板里写四段 `{{#if}}`：

```html
<ul>
  {{#each basics.contacts}}
    <li><span class="k">{{this.label}}</span>{{this.value}}</li>
  {{/each}}
</ul>
```

## 3. `sections`

来源：`resume.data.sections`（`IResumeSection[]`）。

处理规则：

1. 过滤 `visible === false` 的模块
2. 按 `order` 升序排序
3. 过滤每个模块内 `visible === false` 的条目
4. 对条目做**字段归一化**（见 §4）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 模块 id |
| `type` | string | 模块类型，见下表 |
| `name` | string | 用户自定义的模块标题，如「工作经历」 |
| `isText` | boolean | 是否自由文本模块（`summary` 及 `items` 为空且有 `content` 的模块） |
| `content` | string | 纯文本内容（已转义） |
| `contentSafe` | string | 清洗后的 HTML，供 `{{& }}` / `v-html` |
| `items` | array | 归一化条目，见 §4 |
| `isEmpty` | boolean | `items` 为空且 `content` 为空 |

模块类型（`TSectionType`）：

`basics` `summary` `experience` `education` `skills` `projects` `languages` `certificates` `awards` `interests` `custom`

> 注意：`sections` 里通常**不含** `basics`（基本信息走顶层 `basics` 变量）。若用户数据里存在 `type: 'basics'` 的模块，它会被保留但 `items` 为空。

### 3.1 `s` 索引

`s` 是 `sections` 按 `type` 建的索引，方便做**固定布局**（比如左栏放技能、右栏放经历）：

```html
<aside class="left">
  {{#with s.skills}}
    <h2>{{this.name}}</h2>
    {{#each this.items}}<div>{{this.title}}</div>{{/each}}
  {{/with}}
</aside>
```

同 `type` 出现多次时，`s[type]` 取第一个；完整列表始终在 `sections` 里。取不存在的 type 得到 `undefined`，模板里 `{{#if s.awards}}` 判空即可。

## 4. 条目归一化（`IRenderItem`）

这是契约里**最重要的部分**。不同模块的条目字段名不同，归一化为统一的五元组，让模板可以用一套结构渲染所有模块：

| 归一化字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 条目 id |
| `index` | number | 0-based 序号（`@index` 的等价物） |
| `title` | string | 主标题 |
| `subtitle` | string | 副标题 |
| `meta` | string | 补充信息（地点 / 颁发机构 / 链接） |
| `dateRange` | string | 已格式化的时间区间 |
| `description` | string | 描述（纯文本，已转义） |
| `descriptionSafe` | string | 描述（清洗后 HTML，换行已转 `<br>`） |
| `keywords` | string[] | 关键词 / 标签 |
| `raw` | object | **原始条目对象**，需要精确控制时使用 |

### 4.1 各模块的字段映射

| 模块 | `title` | `subtitle` | `meta` | `dateRange` | `description` | `keywords` |
| --- | --- | --- | --- | --- | --- | --- |
| `experience` | `position` | `company` | `location` | `startDate` – `endDate`（`isCurrent` 时右端为「至今」） | `description` | — |
| `education` | `school` | `degree` + `major` | — | `startDate` – `endDate` | `description` | — |
| `skills` | `name` | — | — | — | — | `keywords` |
| `projects` | `name` | — | `url` | `startDate` – `endDate` | `description` | — |
| `languages` | `name` | `level` | — | — | — | — |
| `certificates` | `name` | `issuer` | `url` | `date` | — | — |
| `awards` | `title` ?? `name` | `subtitle` ?? `issuer` | — | `date` | `description` | — |
| `interests` | `title` ?? `name` | — | — | — | `description` | `keywords` |
| `custom` | `title` | `subtitle` | — | `date` | `description` | — |
| 未知类型 | `title` ?? `name` | `subtitle` | — | `date` | `description` | `keywords` |

> `awards` 与 `interests` 在当前 `types/resume.ts` 里**没有专属 interface**（落到 `Record<string, unknown>`）。归一化时按 `title ?? name` 兜底取值，这样即使后续补上专属类型也不破坏模板。

### 4.2 `raw` 的用途

归一化会丢失类型专属字段。需要它们时用 `raw`：

```html
<!-- 技能等级条：level 只存在于 skills 的 raw 里 -->
{{#each s.skills.items}}
  <div class="bar"><i style="width:{{this.raw.level}}0%"></i></div>
{{/each}}
```

```vue
<!-- Vue 引擎里可以做计算 -->
<i :style="{ width: (item.raw.level / 5 * 100) + '%' }" />
```

`raw` 里的值**未经 HTML 转义处理**（它是原始 JSON 值）。用在插值位置 `{{this.raw.x}}` 是安全的（插值统一转义），但**不要**把 `raw` 字段丢给 `{{& }}` 或 `v-html`。

## 5. `helpers`

HTML 引擎里作为过滤器：`{{value | helper(arg)}}`。Vue 引擎里作为方法：`helpers.date(value, 'YYYY.MM')`。

格式化：

| helper | 签名 | 示例 |
| --- | --- | --- |
| `date` | `(value, format?)` | `{{raw.startDate \| date('YYYY年M月')}}` → `2022年3月` |
| `dateRange` | `(start, end, current?, format?)` | `{{raw.startDate \| dateRange(raw.endDate, raw.isCurrent)}}` → `2022.03 – 至今` |
| `join` | `(arr, sep?)` | `{{keywords \| join(' · ')}}`，默认分隔符 ` · ` |
| `truncate` | `(str, n, suffix?)` | `{{description \| truncate(80)}}` |
| `upper` / `lower` | `(str)` | `{{title \| upper}}` |
| `nl2br` | `(str)` | 换行转 `<br />`，输出为 safe 值，可配合 `{{& }}` |
| `default` | `(value, fallback)` | `{{basics.name \| default('你的姓名')}}`，空字符串与空数组也算空 |

数值与比较（比较类返回布尔值，配合 `{{#if}}` 使用）：

| helper | 签名 | 示例 |
| --- | --- | --- |
| `percent` | `(value, max?)` | `{{raw.level \| percent(5)}}` → `100%`，技能条宽度用 |
| `eq` / `ne` | `(value, other)` | `{{#if this.type \| eq('skills')}}…{{/if}}` |
| `gt` / `lt` | `(value, other)` | `{{#if raw.level \| gt(3)}}★{{/if}}` |
| `size` | `(value)` | 数组长度 / 字符串长度 / 对象键数 |

模块与数组筛选（这组是自由分栏的关键）：

| helper | 签名 | 示例 |
| --- | --- | --- |
| `only` | `(sections, ...types)` | `{{#each sections \| only('skills', 'languages')}}` |
| `exclude` | `(sections, ...types)` | `{{#each sections \| exclude('skills', 'languages')}}` |
| `take` | `(arr, n)` | `{{#each this.items \| take(3)}}` 只渲染前 3 条 |

`only` / `exclude` 按条目的 `type` 字段过滤并保持原有顺序。侧栏放技能、主栏放其余模块就靠这两个：

```html
<aside>{{#each sections | only('skills', 'languages')}}…{{/each}}</aside>
<main>{{#each sections | exclude('skills', 'languages')}}…{{/each}}</main>
```

`date` 支持的格式占位：`YYYY` `YY` `MM` `M` `DD` `D` `MMM`（英文月缩写）`MMMM`（英文月全称）。输入解析容忍 `2022`、`2022-03`、`2022-03-15`、`2022/03`、`2022.03`。解析失败时**原样返回**输入字符串，不抛错。

输入精度低于格式要求时，会清掉尾部悬挂的分隔符：`date('2022', 'YYYY.MM')` → `2022`（不是 `2022.`）。但格式里作为后缀的文字会保留：`date('2022/03', 'YYYY年M月')` → `2022年3月`。

过滤器只能调用上表中的白名单函数，不支持任意表达式求值，也不能定义新函数。调用未注册的过滤器会在编译期报错。

## 6. `vars` —— 模板自定义变量

模板在 `config.variables` 里声明可调参数，用户在编辑器右侧面板调整，实际取值出现在 `vars` 里，并**同时注入为 CSS 自定义属性**。

声明：

```json
{
  "variables": [
    { "key": "primaryColor", "label": "主色", "type": "color", "default": "#2563eb", "group": "配色" },
    { "key": "fontSize", "label": "正文字号", "type": "number", "default": 14, "min": 10, "max": 20, "step": 0.5, "group": "排版" },
    { "key": "sectionGap", "label": "模块间距", "type": "length", "default": "16px", "group": "排版" },
    { "key": "showAvatar", "label": "显示头像", "type": "boolean", "default": true, "group": "显示" },
    { "key": "dateFormat", "label": "日期格式", "type": "select", "default": "YYYY.MM",
      "options": [{ "label": "2022.03", "value": "YYYY.MM" }, { "label": "Mar 2022", "value": "MMM YYYY" }] }
  ]
}
```

消费方式有两条，按需选择：

**CSS 变量**（推荐用于纯样式项）。`key` 自动转 kebab-case 并加 `--tpl-` 前缀，也可用 `cssVar` 显式指定：

```css
h1 { color: var(--tpl-primary-color); }
.cv { font-size: var(--tpl-font-size); }
.cv-sec { margin-bottom: var(--tpl-section-gap); }
```

`type: 'number'` 注入 CSS 时会自动补 `px`（如 `--tpl-font-size: 14px`），`vars.fontSize` 里仍是数字 `14`。

**模板变量**（用于逻辑分支）：

```html
{{#if vars.showAvatar}}<img src="{{basics.avatarUrl}}" alt="" />{{/if}}
{{raw.startDate | date(vars.dateFormat)}}
```

取值优先级：

```
variables[].default  →  metadata.theme（仅当 templateVars 缺失）  →  metadata.templateVars
```

中间那一档有条件：**只有 `metadata.templateVars` 整个字段缺失时**，才回退去读旧的 `metadata.theme`。

原因是 `metadata.theme` 永远有值（创建简历时就填了一套默认主题）。如果无条件应用，模板自己声明的变量默认值就永远不会生效 —— 换模板会看不出配色差别。`templateVars` 一旦存在（哪怕是空对象 `{}`），就表示这份简历已进入新的变量体系，此时 `theme` 完全让位。

用户的调整存在 `resume.data.metadata.templateVars` 里，属于**用户数据**，因此换模板不会写坏模板本身，内置模板也能被每个用户各自调参。切换模板时该字段会被重置为 `{}`，让新模板的默认值立即生效。

## 7. `page`

来源：`config.page`（模板声明），可被 `resume.data.metadata.page` 覆写。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `format` | `'a4' \| 'letter'` | 纸张 |
| `widthMm` | number | A4 = 210，Letter = 215.9 |
| `heightMm` | number | A4 = 297，Letter = 279.4 |
| `margin.top/right/bottom/left` | number | 毫米 |

`resume.metadata.page` 整体以及其中各字段都可缺省，**缺省表示跟随模板声明**。这与 `templateVars` 是同一个取舍：如果简历侧总是带着一份页面设置，模板声明的纸张与页边距就永远不会生效。用户在编辑器里调过页边距后，`metadata.page.margin` 才会有值并覆盖模板（四向统一）。

同时注入 CSS 变量，模板直接用即可，不必读 `page.*`：

```css
.cv {
  padding: var(--page-margin-top) var(--page-margin-right)
           var(--page-margin-bottom) var(--page-margin-left);
}
```

`--page-margin-*` 已带 `mm` 单位。页面容器（`.cv-root`）的宽高由渲染器设置，模板**不需要也不应该**自己写 `width: 210mm`。

分页建议：

```css
.cv-sec  { break-inside: avoid; }
.cv-item { break-inside: avoid; }
.page-break { break-before: page; }
```

## 8. 安全约束（模板作者须知）

| 约束 | 说明 |
| --- | --- |
| `{{{ }}}` | **禁止**，编译期报错。需要输出 HTML 用 `{{& }}` |
| `{{& x}}` | 只接受 `contentSafe` / `descriptionSafe` 等以 `Safe` 结尾的字段，或 `nl2br` 的输出。其他值会被拒绝 |
| `v-html` | 同上，只接受 `*Safe` 字段 |
| 标签白名单 | `<script>` `<iframe>` `<object>` `<embed>` `<link>` `<meta>` `<base>` `<form>` `<input>` `<button>` `<svg>` 会被移除 |
| 事件属性 | `on*` 一律剥离 |
| CSS `@import` | 禁止 |
| CSS `url()` | 仅 `data:image/...` 放行；`https://` 视模板信任档位而定；其余拦截 |
| `@font-face` | 默认禁止，需 `capabilities.allowWebFonts` |
| 网络请求 | 沙箱 CSP `connect-src 'none'`，模板无法发起任何请求 |
| Vue `<script>` | 默认被剥离；开启 `capabilities.allowScript` 后可用，但沙箱内无网络、无存储、无法访问父页面 |

信任档位（`trusted` / `owned` / `foreign`）与各档位放开的能力，见设计方案 §8.2。

## 9. 完整示例：单栏 HTML 模板

```html
<article class="cv">
  <header class="head">
    {{#if vars.showAvatar}}
      {{#if basics.avatarUrl}}
        <img class="avatar" src="{{basics.avatarUrl}}" alt="" />
      {{else}}
        <div class="avatar avatar--ph">{{basics.initial}}</div>
      {{/if}}
    {{/if}}

    <div class="head-main">
      <h1>{{basics.name | default('你的姓名')}}</h1>
      <p class="headline">{{basics.headline}}</p>
      <ul class="contacts">
        {{#each basics.contacts}}<li>{{this.value}}</li>{{/each}}
      </ul>
    </div>
  </header>

  {{#each sections}}
    {{#unless this.isEmpty}}
      <section class="sec sec--{{this.type}}">
        <h2>{{this.name}}</h2>

        {{#if this.isText}}
          <div class="rich">{{& this.contentSafe}}</div>
        {{/if}}

        {{#each this.items}}
          <div class="item">
            <div class="item-head">
              <strong>{{this.title}}</strong>
              {{#if this.dateRange}}<span class="date">{{this.dateRange}}</span>{{/if}}
            </div>
            {{#if this.subtitle}}<div class="sub">{{this.subtitle}}{{#if this.meta}} · {{this.meta}}{{/if}}</div>{{/if}}
            {{#if this.descriptionSafe}}<div class="rich">{{& this.descriptionSafe}}</div>{{/if}}
            {{#if this.keywords}}
              <div class="tags">{{#each this.keywords}}<span>{{this}}</span>{{/each}}</div>
            {{/if}}
          </div>
        {{/each}}
      </section>
    {{/unless}}
  {{/each}}
</article>
```
